# @hfb/rating

Pure rating engine for highline freestyle battles: weighted Glicko-2 per format, as defined in
[`rating/rating-specification.md`](../../rating/rating-specification.md). No database, no
network, no clock – the same input always gives the same output.

## Usage

```ts
import { DEFAULT_RULESET_PARAMS, formatRanking, replay } from '@hfb/rating';

const { states, history } = replay({
  rulesets: { 1: DEFAULT_RULESET_PARAMS },
  formats: [{ id: 'combo-3' }],
  estimates: [],
  events: [
    {
      id: 'battle-1',
      formatId: 'combo-3',
      timestamp: Date.UTC(2026, 9, 11),
      level: 3,
      rulesetVersion: 1,
      scoring: 'score', // 'score' | 'points' | 'placement'
      participants: [
        { personId: 'anna', score: 0.75 },
        { personId: 'ben' },
      ],
    },
  ],
});

const ranking = formatRanking(states, Date.now(), DEFAULT_RULESET_PARAMS);
```

For a single new event, create a `RatingEngine` with the participants' current states
(`initialStates`) and call `apply(event)`. It uses the same code as `replay`.

## Files

| File | Contents |
|---|---|
| `src/params.ts` | RuleSet parameters and their default values (spec §1) |
| `src/glicko2.ts` | Glicko-2 core, inactivity, protection rule (spec §2) |
| `src/score.ts` | Points, placements and 5-point scale → score (spec §3) |
| `src/events.ts` | Event format, validation, split into weighted pairs (spec §5) |
| `src/engine.ts` | `RatingEngine`, `replay`, initial estimates, merged formats (spec §2.1, §6, §7) |
| `src/ranking.ts` | Effective RD, ranking value, provisional flag, format ranking (spec §8.1) |

## Tests

- `test/specification.test.ts` – the test values of spec §11.
- `test/reference.test.ts` – replays seeded random histories and compares every value with the
  Python reference. The fixtures in `test/fixtures/` are generated by
  `python rating/export_fixtures.py`; regenerate them whenever `glicko_sim.py` changes.
- `test/engine.test.ts` – behaviour: groups, protection rule, estimates, merging, validation.
